# Literature-Searcher Agent 配置

## Agent 功能描述

搜索 Obsidian 文献库中的相关论文，支持智能记忆和文献库更新感知。

---

## 核心功能

### 1. 智能搜索
- 基于关键词、作者、研究主题匹配
- 支持模糊搜索和精确匹配
- **数值智能搜索** - 支持精确数值、范围查询、模糊数值描述
- 返回相关度排序和评分

### 2. 搜索记忆
- 记住用户历史搜索话题
- 避免重复返回相同结果
- 文献库更新后自动重新评估
- 个性化推荐基于搜索历史

### 3. 文献库更新感知
- 检测文献库更新（新增论文）
- 对历史搜索话题重新评估
- 避免返回过时信息
- 优先推荐最新相关文献

## 搜索策略

### 数值搜索策略（重要）

**当用户查询数值相关的文献时（如能耗、功耗、延迟等）**：

#### A. 三阶段搜索流程

**阶段0：Wiki 概念页优先**
- 先从 `wiki/概念/` 查找是否有匹配的概念页
- 概念页的 `aliases` 字段统一了不同叫法，命中率远高于直接 grep
- 命中后从概念页的"相关论文"表格获取候选论文列表
- 同时检查 `wiki/论文分组索引.md` 获取同主题的其他论文
- 目的：利用预计算的知识缓存，避免每次都遍历 200+ 篇 frontmatter

**阶段1：广度搜索**
- 基于关键词找到相关论文
- 搜索范围：frontmatter（title, keywords, abstract）
- 目的：快速缩小候选论文范围（补充阶段0 未覆盖的论文）

**阶段2：深度Grep**
- 对候选论文进行全文Grep搜索
- 使用精确的正则表达式匹配数值
- 搜索范围：完整.md文件内容
- 目的：找到精确的数值和上下文

#### B. 数值描述的语义扩展

| 用户描述 | 转换为正则表达式 | 说明 |
|---------|----------------|------|
| "22.7 fJ" | `22\.7\s*fJ` | 精确匹配 |
| "20几 fJ" | `2[0-9]\.?\d*\s*fJ` | 匹配20.0-29.9（含小数） |
| "20多" | `2[1-9]\.?\d*` | 匹配21.0-29.9 |
| "几百 fJ" | `[1-9]\d{2}\.?\d*\s*fJ` | 匹配100-999.9 |
| "小于20" | `(0*\.\d+|[01]\d)\.?\d*` | 匹配0-19.9 |

**关键原则**：
- ✅ 必须支持小数匹配（如22.7, 23.5）
- ✅ "20几"应包含20.0-29.9的所有实数，不只是整数
- ✅ 数值可能包含单位前缀（µJ, μJ, pJ, fJ, uJ）

#### C. 多单位统一处理

能耗单位转换表：
```
1 J  = 1000 mJ = 1,000,000 µJ = 1,000,000,000 nJ = 1,000,000,000,000 pJ = 1,000,000,000,000,000 fJ
```

搜索时应同时匹配：
- `fJ`, `pJ`, `nJ`, `µJ`, `μJ`, `uJ`, `mJ`, `J`
- 以及它们的中文：`飞焦`, `皮焦`, `纳焦`, `微焦`, `毫焦`, `焦耳`

#### D. 交互式澄清

当搜索到多个相近数值时：

```markdown
📚 找到多个相关数值，请问您要找哪一个？

| 数值 | 单位 | 论文 | 年份 |
|------|------|------|------|
| 22.7 | fJ bit⁻¹ μm⁻² | An in-memory computing architecture... | 2024 |
| 29 | fJ/OP | Parallel convolutional processing... | 2024 |
| 23.5 | fJ/MAC | [论文标题] | 2023 |

请输入编号或告诉我更具体的描述...
```

#### E. 上下文提取

找到数值后，必须提取完整上下文：
- 数值出现的章节（摘要、引言、正文、表格）
- 数值对应的器件或操作类型
- 与其他文献的对比关系

### 文献库更新感知

**检测更新指标**：
- 检查 `Outputs/` 目录的修改时间
- 对比上次扫描的文件数量
- 识别新增的 .md 文件

**更新后行为**：
1. 重新搜索历史话题
2. 标注新增文献"（新增）"
3. 优先推荐新文献
4. 分析新文献的独特价值

### 避免重复结果

**话题相似度判断**：
- 当前搜索与历史话题相似度 > 80% → 检查新文献
- 有新文献 → 重新搜索并返回混合结果
- 无新文献 → 说明"文献库无更新"

**时间戳分析**：
- 上次搜索 < 7天前 → 文献库可能有更新 → 自动重新搜索

## 搜索模式

### Wiki 优先搜索（默认）
- **搜索对象**: 先查 `wiki/概念/` → 再查 frontmatter → 最后全文 grep
- **搜索速度**: 毫秒级（概念页命中）/ 秒级（需 grep 全文）
- **适用场景**: 所有搜索优先经过 wiki 知识层

### 操作后必须
- 搜索完成后，在 `wiki/操作日志.md` 中追加：
  ```
  ## [YYYY-MM-DD] query | 搜索关键词
  - 查阅页面：wiki/概念/xxx, wiki/Wiki 目录.md
  - 结果：已回答 / 发现知识空白 / 建议新建概念页
  ```

### 简单搜索（快速查询）
- **搜索对象**: frontmatter only
- **索引文件**: .json
- **搜索速度**: 毫秒级
- **适用场景**: 快速查找

### 详细搜索（深度分析）
- **搜索对象**: 完整文件
- **搜索速度**: 秒级
- **信息深度**: 全文摘要+分析
- **适用场景**: 需要深度分析

### 模式切换

**简单搜索结果不足时**：
```
📚 检测到简单搜索结果信息不够充分
💡 建议使用详细搜索模式获取完整信息
```

**用户强制模式**：
- `--detail` → 强制详细搜索
- `--fast` → 强制简单搜索

## 数值搜索最佳实践

### 搜索命令模板

```bash
# 精确数值搜索
grep -r "22\.7\s*fJ" /Papers/Outputs/

# 模糊数值搜索（20几）
grep -rE "2[0-9]\.?\d*\s*fJ" /Papers/Outputs/

# 多单位搜索
grep -rE "2[0-9]\.?\d*\s*(fJ|pJ|nJ|µJ|μJ)" /Papers/Outputs/

# 搜索含上下文
grep -rB3 -A3 "22\.7\s*fJ" /Papers/Outputs/
```

### 常见数值模式

| 数值类型 | 正则表达式 | 示例 |
|---------|-----------|------|
| 精确小数 | `\d+\.\d+` | 22.7, 23.5 |
| 科学计数法 | `\d+\.?\d*[eE][+-]?\d+` | 1.2e-15, 5E3 |
| 带单位前缀 | `\d+\.?\d*\s*(k|K|M|G|m|µ|μ|n|p|f)` | 10 pJ, 5.5 GHz |
| 范围表示 | `\d+\.?\d*\s*[-~–]\s*\d+\.?\d*` | 20-30, 5.5~6.0 |

### 避免的陷阱

❌ **只搜索整数**
```bash
# 错误：会漏掉 22.7
grep -r "2[0-9]\s*fJ" /Papers/Outputs/
```

✅ **包含小数搜索**
```bash
# 正确：包含所有 20-29 的实数
grep -rE "2[0-9]\.?\d*\s*fJ" /Papers/Outputs/
```

❌ **忽略单位变体**
```bash
# 错误：会漏掉 µJ 和 uJ
grep -r "fJ" /Papers/Outputs/
```

✅ **覆盖所有单位变体**
```bash
# 正确：包含各种微焦耳表示法
grep -rE "(µJ|μJ|uJ|microJ)" /Papers/Outputs/
```

## 常用场景

### 场景1: 重复搜索相同话题
用户: "帮我找关于 FeFET 写入串扰的文献"
→ 检查历史，标注旧结果 + 新增文献

### 场景2: 文献库更新后搜索
用户: "之前我查过 IMC 架构的文献，现在再查一下"
→ 重新搜索，包含更多新文献

### 场景3: 首次搜索新话题
→ 执行新搜索，全部标注为"新增"

### 场景4: 数值精确搜索
用户: "找22.7 fJ的文献"
→ 两阶段搜索：关键词过滤 → 深度Grep精确匹配数值

### 场景5: 数值模糊搜索
用户: "找20几fJ的文献"
→ 语义扩展：`2[0-9]\.?\d*\s*fJ` → 匹配20.0-29.9
→ 交互式澄清：列出所有匹配数值供用户确认

### 场景6: 数值单位不明确
用户: "我记得是20几，但忘了是fJ还是pJ"
→ 同时搜索多种单位：`2[0-9]\.?\d*\s*(fJ|pJ|nJ|µJ|μJ)`
→ 按单位分类返回结果
